Matching: an object or TC "has" a sim if more than 75% of its hits match that sim (the ntuple's matchfrac). The
ntuple's *IdxAll lists hold ONLY matches above 0.75, so partial matches (e.g. a 7/10 T5) count as "fake" here.

METHOD
 * b01/b02/b05: per-sim, per-stage matched objects; T5 fates from t5_isDupBits (bit0 AfterBuild, bit1 BeforeTC,
   bit4 CrossCleanT5), partOfPT5, tightCutFlag.
 * Exact offline REPLAYS of the dedup kernels, rebuilding hit identities from MD/pLS hit coordinates:
     - RemoveDupQuintupletsAfterBuild: agrees with bit0 for 66534/66534 sim-matched T5s       (b04)
     - RemoveDupQuintupletsBeforeTC  : agrees with bit1 for 1177/1185 non-pT5 T5s              (b04)

     - BeforeTC -> CrossCleanT5 -> AddT5asTrackCandidate: reproduces 2175/2176 T5 TCs           (b11)
   Because the replays match, the counterfactuals for these stages (b11, b13, b15) are exact. The exceptions are
   the neglected CrossCleanpLS/CrossCleanT4 side effects, and T5s that AfterBuild had killed, whose pT5 building
   cannot be replayed.
 * Creation-time cuts are invisible. They are inferred when a sim has the lower objects but not the higher one.

2) SPECIFIC CUTS AT THE BIG STAGES
 [S1] tightCutFlag is never set for T5s with inner-pT > 100 GeV. MEASURED: tight = 0 for 13923/13923 sim-matched T5s
      with t5_pt > 100; tight = 1 for 90% below 100.
      Code: Quintuplet.h passT5RZConstraint. The `inner_pt > 100 || NaN` branch returns `rzChiSquared < 4.677` before
      tightCutFlag is ever assigned. The flag arrives as false (CreateQuintuplets initialises it false, then
      `tightCutFlag and inference`).
      AddT5asTrackCandidate requires tightCutFlag, so a T5 above 100 GeV can never become a T5 TC; it can only be
      found through a pT5. This looks like a bug.
      The fix on its own recovers 0 sims, because those T5s are also killed by [S2] (b11).
 [S2] RemoveDupQuintupletsBeforeTC plus CrossCleanT5 remove distinct core tracks.
      Kill condition: [(dR2<1e-3 or nShared>=5) and d2emb<1] or [dR2<0.02 and d2emb<0.1]. dR2 uses the T5
      position eta/phi (anchor of MD 2). A partOfPT5 T5 always wins.
      In the core essentially every neighbour pair has dR2 < 1e-3 (a 0.032 cone).
      For lost core sims (b10):
        - 22132/22276 kill pairs pass through the dR2<1e-3 branch
        - 15896/22276 kills share 0 hits with the victim
        - median embedding d2 = 0.30, so the embedding does not separate neighbouring jet tracks
        - 15022/22276 kills come from the partOfPT5 priority branch
        - killers: 65% fake T5s, 33% other-sim T5s, 2% own-sim T5s
      CrossCleanT5 applies the same embedding test against every pT5 (including duplicates). Relaxing BeforeTC
      alone is therefore undone by CrossCleanT5; both have to change.
      Of the 276 core sims in this bucket, 157 have no tight T5 ([S1]) and 119 have a tight T5 killed by the dedup.
      Ceiling (tight fix plus no BeforeTC/CrossCleanT5): +281 core, but +40.8k fake T5 TCs, because after AfterBuild
      the T5 pool is mostly fakes. The dedup does needed fake removal, so the fix must be selective (see 3).
      Discriminators among T5s this would rescue (b11_dump):
        - T5 score_rphisum median: 2.4 for rescued real tracks vs 154 for fakes
        - T5 pT median: 81 GeV vs 7 GeV
        - T5 DNN score separates weakly: median 0.81 vs 0.62
 [S3] pT5 dedup keeps the wrong pT5 (RemoveDupPixelQuintupletsFromMap). The rank is the pT5 rPhiChiSquared, i.e. the
      T5 hits fitted to the pixel-seed circle, which is poorly constrained at high pT. Median victim pLS pT is 84 GeV.
      What beat the own pT5 for the 78 core sims (473 kill rows, b09):
        - the same pLS with a fake (mixed-hit) T5: 215 rows
        - the same pLS with another own T5, which was itself killed in turn (the dedup is not transitive): 161 rows
        - other combinations: the rest
      Exact counterfactuals (b13):
        - oracle ranking: +101 core / +52 mid / +9 noncore
        - rank by pT5chi2*(1-T5dnn): +29 / +28 / +8, with fake pT5 TCs -40
        - rank by T5 score_rphisum: +33 / +17 / +1, with fake pT5 TCs +47
 [S4] ExtendTrackCandidatesFromDupT5 breaks TC matching. Extra layers taken from duplicate T5s (>=8 shared hits,
      d2emb<1) add another track's hits. 34 sims had a matching pT5 object but an unmatched final TC:
      26 core / 7 mid / 1 noncore. Extension never creates a match (0 gains). MEASURED and exact (b14).
 [S5] pT5 hijack (52 core). The own T5 is paired at pT5 building with another track's pLS. 67 of the 68 surviving
      absorbing pT5 TCs are fakes. partOfPT5 is set at creation and stays set even if that pT5 later loses the
      dedup, so the T5 can never be a T5 TC.
      If no fake pT5 had been built (oracle), core gains +101, the same as the pT5-dedup oracle: the freed T5s then
      die in [S1]/[S2].
 [S6] AfterBuild dedup (49 core). This is the same lower module, >=7 shared hits, keeping the lowest
      score_rphisum. For the 35 core sims checked, the surviving T5s hold only 4-7 of the sim's own hits: mixtures
      that pass the chi2 ranking. The counterfactual cannot be replayed, because pT5 building for the restored T5s is
      unknown.
 [S7] pLS-only route for tracks with <5 OT layers. pLS TCs need quad seeds. Core finds 9/84 such sims, noncore
      70/153. Of the 24 core quad pLSs that were killed, 16 share hits only with fake pLSs and 6 share hits with
      another sim's pLS.

4) TOP RECOMMENDATION
 Fix the T5 -> T5-TC gate for dense, high-pT cores. Three parts:
  (i)   In passT5RZConstraint, set tightCutFlag in the inner_pt>100 / NaN branch. It is currently never set, so every
        T5 above 100 GeV is barred from being a TC.
  (ii)  In RemoveDupQuintupletsBeforeTC and CrossCleanT5, stop removing a well-fitted, high-pT T5 on angular and
        embedding proximity alone. For T5s with score_rphisum<3 and pT>50, require >=5 shared hits (>=3 against a
        pT3's T3).
        Measured: +42 core, +12 mid, +4 noncore for +35 fake TCs.
        With pT>20 instead: +66 core, +30 mid, +8 noncore for +154 fakes.
  (iii) Change the pT5 dedup rank from pT5 rPhiChiSquared to one that includes T5 quality, e.g.
        pT5chi2*(1-T5dnn). Measured: +29 core, +28 mid, +8 noncore, fakes not increased.
 Together, (i)+(ii)+(iii) give +71 core sims per 99 events (0.538 -> about 0.60) at an unchanged fake rate.
 Restricting the TC hit extension in dense regions adds about +26 core.
 Biggest single lever: (i)+(ii). That is the 22.8%-of-core bucket and the only route for the 23% of core tracks
 without a matched pixel seed.
 Validation needs a GPU run with these changes on independent events (user approval required). The CrossCleanpLS
 and T4 interplay of the new T5 TCs is not replayed offline.
